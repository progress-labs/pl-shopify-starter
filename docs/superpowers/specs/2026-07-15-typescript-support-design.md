# TypeScript Support — Design

**Date:** 2026-07-15
**Status:** Approved (design); implementation plan not yet written
**Base:** `origin/main` @ `0c3a703`
**Branch:** `typescript-support`

## Goal

Convert the `frontend/` runtime to TypeScript, with type errors blocking the build. Four
motivations, all weighted equally: catch real bugs, editor autocomplete, typed island
contracts, and establishing TS as the house convention.

## What we measured

Rather than estimate migration cost, we ran `tsc` against the existing JS at two strictness
tiers. Measured against `origin/main` @ `0c3a703` (28 source files + 4 test files):

| Tier                                    | Source errors | Test errors |
| --------------------------------------- | ------------- | ----------- |
| `strict: true`                          | 295           | 52          |
| No `strictNullChecks` / `noImplicitAny` | 81            | 37          |

The ~214-error gap is almost entirely the null family (`TS2531`/`TS2532`/`TS18047`/`TS2533`
= 138 errors), overwhelmingly from `querySelector` returning `T | null`. **That gap is the
central design question**, and Phase 0 exists mostly to answer it once instead of 138 times.

### Honest read on bug-catching

TypeScript found **one** unambiguous live bug, not a pile of them:

`frontend/islands/product-form.js:46`

```js
if (this.submitButton.getAttribute('aria-disabled') === true) return
```

`getAttribute()` returns `string | null` — never a boolean. The comparison is **always
false**, so the double-submit guard never fires. Line 49 writes the attribute as `true`,
which the DOM coerces to the string `"true"`; the intent was plainly `=== 'true'`. A fast
double-click on Add to Cart dispatches two `cart:add` events and adds the item twice.
`this.pending` is set but never checked on the submit path, so nothing else catches it.

This is caught at the **loosest** tier — it does not require strict mode.

Beyond that: one robustness issue (`parseInt(formData.get('quantity'))` — `get()` returns
`string | File | null`, and `parseInt` on a `File` yields `NaN`), and ~9 sloppy-but-harmless
coercions like `setAttribute('aria-hidden', true)` where the DOM stringifies correctly.

So the bug-catching payoff on _existing_ code is modest. The real return is on code not yet
written, and on the typed event/island contracts from Phase 1. We should be honest about
that rather than justify the project on a bug count.

### Existing JSDoc is an asset

`cart-events.js` already defines proper `@typedef`s (`CartAddDetail`, `CartAddedDetail`,
`CartErrorDetail`), and `cart-api.js` does cross-file `import('./cart-events').CartAddDetail`.
Much of the type design is already written; it needs promoting, not inventing.

## Approach

**Full conversion to `.ts` at `strict: true`, with the null tax paid once via a typed query
helper, rolled out in batches behind a dual-extension glob.**

Alternatives rejected:

- **Full strict, hand-written null guards.** Same endpoint, but ~138 hand-written checks
  against elements Liquid already guarantees. Ceremony, not safety.
- **JSDoc + `checkJs`, no renames.** Zero file churn and it catches the product-form bug,
  but delivers neither typed island contracts nor the house convention. JSDoc generics get
  painful fast.

### Transitional compatibility — deliberate and time-boxed

We do **not** need backwards compatibility with existing modules as a permanent goal. But
batching requires `.js` and `.ts` to coexist _during the migration window_. That is
transitional scaffolding with an explicit removal step (Phase 5), not a compat layer. If
Phase 5 is skipped, the scaffolding silently becomes permanent — which is exactly the
outcome we are trying to avoid.

## Extension coupling — the highest-risk surface

The `.js` extension is hardcoded in **three** places. All must stay consistent or islands
silently stop hydrating (no console error — `islands[path]` is `undefined`, the `if` never
fires, and the page is simply dead):

1. `frontend/lib/revive.js:74` — `import.meta.glob('@/islands/*.js')`
2. `frontend/lib/revive.js:97` — `` const potentialJsPath = `/frontend/islands/${tagName}.js` ``
3. `layout/theme.liquid:70` and `layout/password.liquid:56` — `render 'vite-tag' with 'theme.js'`

(3) is easy to miss: it is Liquid, not JS, and it is only reachable when the **entrypoint**
`theme.js` is renamed. `snippets/vite-tag.liquid` is generated by vite-plugin-shopify and
must be regenerated by a build after that rename.

> **Operational note, unrelated to TypeScript.** `snippets/vite-tag.liquid` is tracked in git
> but auto-generated, and is listed in `.prettierignore` but **not** `.gitignore`. Running
> `npm run dev` rewrites it to point at `http://localhost:5175`. If that dev output is ever
> committed and deployed, the live storefront loads its JS from localhost and breaks for every
> visitor. Worth adding to `.gitignore` — tracked separately from this work.

## Phase 0 — Infrastructure (no renames)

Independently verifiable: site behaves identically, `npm run typecheck` passes trivially,
nothing renamed.

- **`tsconfig.json`** replaces `jsconfig.json`; same `@/*` and `~/*` paths. `strict: true`
  from day one so no file is ever converted at a strictness we later re-tighten.
  `allowJs: true`, and **`checkJs: false`** during the window — unconverted `.js` must not
  flood the build with the 81 errors before we're ready. Each batch opts in by renaming.
  `"types": ["vite/client", "vitest/globals"]`.
- **Dual-extension glob** in `revive.ts` — the piece that makes batching safe:

  ```ts
  export const islands = import.meta.glob('@/islands/*.{js,ts}')

  const mod =
    islands[`/frontend/islands/${tagName}.ts`] ??
    islands[`/frontend/islands/${tagName}.js`]
  if (isPotentialCustomElementName && mod) {
    /* … */
  }
  ```

- **`frontend/types/globals.d.ts`** — ambient declarations for `window.routes`,
  `window.cartStrings`, `window.variantStrings` (11 errors), plus an `HTMLElementTagNameMap`
  augmentation so `document.querySelector('cart-drawer')` returns `CartDrawer`. This is what
  makes `cart-api.js`'s `cartDrawer.getSectionsToRender()` type-check honestly rather than
  via a cast.
- **`frontend/lib/dom.ts`** — the helper absorbing the 138 null errors:

  ```ts
  function must<K extends keyof HTMLElementTagNameMap>(
    root: ParentNode,
    sel: K
  ): HTMLElementTagNameMap[K]
  function must<T extends HTMLElement = HTMLElement>(
    root: ParentNode,
    sel: string
  ): T
  ```

  Throws when the element is missing. Converts ~138 type errors into mechanical call-site
  swaps **and** upgrades a silent `undefined`-method crash into a loud failure at hydration
  when a section setting removes an element. The null work becomes a feature, not a toll.

- **Enforcement** — `"typecheck": "tsc --noEmit"`, wired into `build` and `deploy` beside the
  existing `vitest run`. Vite/esbuild strips types **without checking them**, so without this
  a type error ships green and "we have TypeScript" is decoration.
- **Tooling** — add `typescript-eslint` to the flat config. Prettier already handles `.ts`.

## Phases 1–4 — Conversion batches

**Batch 1 — `lib/` (8 source + 4 tests). Must go first.** Islands import from it; converting
it first means every later batch inherits real types instead of `any`. It also carries the
highest-value work: giving `dispatchCartEvent`/`onCartEvent` a `CartEventMap` turns the
string-keyed event bus into a checked contract — the thing most likely to catch a _future_
bug.

Files: `utils`, `a11y`, `cart-events`, `cart-api`, `cart-init`, `cart-live-region`, `revive`,
`sentry`.

Then islands in three cohesive batches, each a reviewable domain that can be QA'd as a unit:

- **Batch 2 — cart (5):** `cart-drawer`, `cart-drawer-items`, `cart-items`, `cart-note`,
  `cart-remove-button`
- **Batch 3 — product (6):** `product-form`, `variant-radios`, `variant-selects`,
  `selling-plan-picker`, `quantity-input`, `product-recommendations`
- **Batch 4 — UI/chrome (8):** `header-drawer`, `sticky-header`, `details-modal`,
  `details-disclosure`, `password-modal`, `localization-form`, `video-player`,
  `newsletter-form`

The 4 `*.test.js` files convert **alongside their subjects**, not in a lump. Their 52 errors
are mostly `Cannot find name 'global'` (resolved by the `types` setting above) and mocks that
don't match real signatures — which is the checker doing its job: a mock that can't
type-check against the real function is a test that isn't testing the real function.

Batch 3 fixes the `product-form.js:46` bug. It should ship with a regression test for the
double-submit guard, since the type fix and the behavior fix are separable and the behavior
is the part that matters.

## Phase 5 — Remove the scaffolding

Not optional; this is the phase that keeps the transitional state from becoming permanent.

- Glob narrows to `import.meta.glob('@/islands/*.ts')`; restore single-path lookup.
- Rename entrypoint `theme.js` → `theme.ts`; update `layout/theme.liquid:70` and
  `layout/password.liquid:56` to `render 'vite-tag' with 'theme.ts'`; rebuild to regenerate
  `snippets/vite-tag.liquid`.
- `allowJs: false`; delete `jsconfig.json`.

## Known friction

Surfaced now so it isn't discovered mid-batch. All of it lands in Batch 1:

- `strict` enables `useUnknownInCatchVariables`: the ~6 `catch (e) { … e.message }` blocks in
  `cart-api.js` need `e instanceof Error` narrowing.
- `CartAddRequestBody` builds `const body = {…}` then conditionally assigns `body.properties`
  / `body.selling_plan`. TS infers the narrow object literal and rejects the assignment —
  needs an explicit annotation on `body`.

## Out of scope

- Typing Liquid/section schema.
- Runtime validation of Shopify API responses (typed as interfaces; not validated at runtime).
- The `.gitignore` fix for `vite-tag.liquid` (real, but a separate concern).
- Any refactor beyond what the type checker forces.

## Risks

| Risk                                                          | Mitigation                                                                           |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Extension mismatch silently kills all hydration               | Dual glob in Phase 0; QA each batch by loading a page per island                     |
| Type error ships green                                        | `tsc --noEmit` blocking `build` + `deploy` (Phase 0)                                 |
| Phase 5 never happens; dual-extension state becomes permanent | Phase 5 tracked as its own PR, not a cleanup afterthought                            |
| `must()` throws in production where JS silently no-op'd       | Intentional — but Batch 2+ QA must exercise sections with optional settings disabled |
